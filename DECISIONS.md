Authority order when documents conflict: 03, 02, 04, 05, 06, 01, 07 (Doc 00 §2).

## Developer decisions (open for review)

| # | Decision | Reason |
| --- | --- | --- |
| D-01 | Stack: Vite, React 19, TypeScript, Tailwind v4, Vitest, vite-plugin-pwa, react-router (HashRouter). | Doc 05 §1 leaves the stack open. HashRouter and a relative base let the built app run from any static host or path, and offline. |
| D-02 | Inter is bundled with `@fontsource-variable/inter`, not loaded from Google Fonts. | Doc 04 asks for Inter. A CDN font would break offline use. Cost: about 200 KB of extra precache; can be trimmed to Latin subsets later. |
| D-03 | Placeholder PWA icons are generated by `scripts/gen-icons.mjs` (teal tile, three bars). | Doc 04 §2 says the logo is handled separately. Replace when the real logo exists. |
| D-04 | Mobile "Lagi" is a page (`/lagi`) for now, not a bottom sheet. | Keeps Phase 1 simple. Doc 04 §3 asks for a sheet, so this is revisited in the UI polish pass. |
| D-05 | Routes, nav order and labels follow Doc 02 §1 and Doc 01 §6. | Direct from spec. |
| D-06 | When something needed is missing or invalid, `computeMenuCost` returns an incomplete result that lists issue codes and only the components it could calculate. It omits full cost, profit and margin instead of guessing. | Doc 03 §8: never divide by zero, never assume zero overhead. |
| D-07 | A yield or selling price of zero or less is an incomplete state (`yield_invalid`, `selling_price_invalid`). | Both are denominators in Doc 03 §4 and §10. The spec does not name them. |
| D-08 | Expected sales of zero, missing or invalid is incomplete even if shared operating costs are also zero. | Strict reading of Doc 03 §8. Easy to relax if you prefer. |
| D-09 | Status comparisons allow a 1e-9 tolerance, so floating-point noise (for example −1e-16) is not called a loss. | Doc 03 §14 says to calculate at full precision. |
| D-10 | In Ruang Kerja, if both floor areas are given they decide the percentage, otherwise the manual % is used. | Doc 02 §7 says areas "derive" the percentage. |
| D-11 | Each Kos Operasi category is one row. `classification: direct` removes a row from the shared total. In Lebih Tepat, Elektrik holds only the remaining general shared amount; production appliances are costed per recipe. | Doc 03 §9 and Doc 02 §9. This is how the engine enforces "no double count". |
| D-12 | A negative value that rounds to zero displays as `RM0.00` with no sign. Display uses thousands grouping (`RM2,000.00`). | Doc 03 §14 preserves sign for real negatives. |
| D-13 | Pack-to-unit mappings (for example 1 pek = 12 biji) live on the ingredient and are optional. | Decision A-05. |
| D-14 | A custom scenario may be any finite percentage above −100%. | Doc 02 §12 lists "Custom" without limits. |
| D-15 | Reference fixtures split the Doc 03 §15 per-portion figures into real inputs (chicken RM15/kg at 120 g and 80 g). The sample chicken weights are invented for tests. | Needed to make M01/M02 and the chicken scenarios testable. |
| D-16 | Operating-cost detail (workspace, water, electricity) is embedded on the `OperatingCostRow`, with a unique `[businessId+category]` index. | One row per category and no duplicate on mode switch (Doc 06 §5); avoids separate detail tables to keep in sync. |
| D-17 | Derived values are never stored: ingredient/packaging unit cost, operating-cost rate, final monthly amount. `RecipeIngredient` has no cached cost. | Doc 05 §3 and §10: one authoritative source per value. |
| D-18 | A history record is appended when price, package quantity or package unit changes (unit compared ignoring case/spaces). Name, active flag and pack mappings alone append nothing. Exactly one record per update, even if several fields changed. | Doc 05 §5. Pack-mapping edits are a judgement call; say if you want them tracked. |
| D-19 | `purchaseDate` defaults to the device's local calendar date, and can be set by the user (back-dating allowed). History is ordered by date, then by `seq`. Backfill uses the ingredient's `createdAt` date. | Malaysian users' "today" is local, not UTC. `seq` breaks same-day ties. |
| D-20 | Any non-blank unit is accepted as a package unit; unknown units are treated as counted units (for example `biji`, `kotak`). Blank units, non-positive quantities, negative prices and blank names are rejected before anything is written. | Custom counted units are normal in F&B. |
| D-21 | The database blocks updates and deletes on `priceHistory` (Dexie hooks) and enforces unique `[ingredientId+seq]`. | Doc 05 §5 immutability. |
| D-22 | Ingredient + history writes share one transaction; a failed history write rolls back the ingredient change. | No ingredient without history, no history without its ingredient. |
